# 轻量开发小队

在保证正确性与必要验证的前提下，用局部上下文、任务合并、代理复用和适度推理降低完整开发任务的消耗。

## 使用

显式调用 `$dev-team-lite`，或说“使用轻量开发小队完成订单导出功能”。需求明确且已有授权时直接推进；希望先审方案时加上“先让我确认计划”。普通开发请求和对 Skill 本身的讨论不启用本流程。

将完整 `dev-team-lite` 文件夹放入宿主支持的技能目录，例如 Codex 的 `~/.codex/skills/dev-team-lite/`。保留 references 文件，运行时按需读取。不需要安装额外依赖。

## 主要规则

- 主代理统筹并承担自己的独立工作；子代理完成边界清晰的实现、测试与修复。
- 简单任务直接处理；规划、探索和审查按收益启用，不固定创建角色。
- 首次创建代理默认使用无历史模式并提供必要局部上下文，无论是否覆盖模型。
- 合并共享大量上下文的任务，复用相关代理，只传必要差异。
- 默认继承模型配置；具备可靠信息时按任务选择充分且适度的推理强度。
- 保留唯一写入者、权限边界、正常调试与集成验证；不按修复次数机械放弃任务。
- 正常等待不视为故障；结果不明的有副作用调用先核实再考虑重试。

相较标准 dev-team，Lite 使用相同的职责与质量边界，更明确地约束首次历史传递、上下文复用和推理资源选择。它不承诺固定比例的 Token 或费用下降。

`evals/cases.md` 提供待运行的行为和效率场景，清单不代表测试通过。比较效率时应包含主代理和子代理的总消耗、耗时、返工及完成质量。
