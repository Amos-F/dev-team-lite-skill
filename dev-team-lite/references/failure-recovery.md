# 故障恢复

先区分开发反馈、正常等待与工具故障，只暂停真正受影响的工作。

| 情况 | 处理 |
| --- | --- |
| 编译、测试或业务行为失败 | 根据证据在原任务范围修复并针对性验证；不是工具重试 |
| 正常等待窗口结束 | 代理仍可能正常运行；结合状态和任务耗时继续有界等待，不因缺少新输出判定失败 |
| 参数或路径填写错误 | 查明原因并纠正后可再调用一次；禁止原样重复失败调用 |
| 权限拒绝、能力确实缺失 | 不绕过限制；按宿主审批机制处理，或报告受影响分支阻塞 |
| 临时连接或服务故障 | 先核实操作是否已发生；安全且有恢复依据时最多一次修复性重试 |
| 代理返回失败 | 保留已有结果，判断是否可通过一次明确的任务修订继续；不连续创建替代代理 |

创建代理、启动进程、修改文件或外部操作的调用结果不明时，优先通过状态、任务标识或幂等机制核实。不能核实且重复操作可能产生额外副作用时，暂停该分支，不直接重试。

每个故障事件最多一次修复性重试；不能靠改名或创建替代代理刷新预算。子代理仍失败时返回原始错误、已发生的操作和现有状态，主代理先核实这些信息，不能无条件重发同一失败操作。

等待采用宿主支持的有界等待或完成通知，并遵守单次等待限制，避免高频查询。长任务按已知预期耗时、进程状态和进展判断是否干预；出现明确卡死证据、用户要求停止或任务截止时间到达时中断并报告。正常运行但尚未完成时，不把任务报告为完成。

多个失败只有存在共同故障证据时才暂停相关调度，不按失败分支数量自动终止全部工作。服务整体不可用时停止新增代理，但可完成不依赖该服务且安全的本地工作。

转交失败任务前确认原代理及其后台进程已停止写入。报告阻塞原因、已完成结果、未完成范围和所需下一步；无需用户决策且可安全恢复时自行处理。
