# 变更处理

用户修改需求、约束或验收标准时：

1. 对照现有任务识别受影响的行为、接口、文件和验证。
2. 暂停尚未分派的受影响部分；中断正在实施失效假设的代理，并确认它及相关进程停止写入。
3. 未受影响任务继续沿用原有授权和契约；已完成结果经过兼容性检查后复用。不要撤销整个任务的授权。
4. 更新受影响任务的说明与所有权。现有授权内的明确修订直接继续；仅对重要歧义、范围扩大或缺失权限询问用户。
5. 用户要求计划审批时，对受影响部分提供修订计划，得到当前修订的明确确认后恢复；不把问题、沉默或对旧方案的确认视为批准。

用户明确暂停或取消整个任务时，停止全部相关分派与写入。保留工作状态，不擅自回滚已有改动。无法确认原写入者停止时，不转交其文件给新写入者。
